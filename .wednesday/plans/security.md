## 2. Data Classification

| Data Category | Classification | Handling |
|---|---|---|
| Real NJDG aggregate statistics | **Public** — safe to display | Must be attributed to source; never altered |
| Synthetic case records | **Internal prototype data** | Must be labelled `SYNTHETIC` everywhere; never presented as real cases |
| Synthetic case events | **Internal prototype data** | Same as above |
| Synthetic party identifiers | **Anonymised** | No real names; use generated pseudonyms or "Party A / Party B" |
| Synthetic CNR-like identifiers | **Anonymised** | Must include "SYN/" prefix to distinguish from real CNRs |
| Triage scores and evidence bundles | **Internal prototype** | Restricted to authenticated users only |
| User credentials (admin, registry_staff) | **Confidential** | Hashed (bcrypt); never logged; never returned in API responses |
| JWT tokens | **Session credential** | Short expiry (e.g., 8 hours for prototype); not stored server-side |

## 3. Auth Strategy Recommendation

### Token Approach (JWT HS256)

```
POST /auth/token → returns {access_token, token_type: "bearer", role, expires_in}
  - Payload: {sub: username, role: "admin"|"registry_staff", exp: now+8h}
  - Secret: from environment variable JWT_SECRET (never hardcoded)
  - Algorithm: HS256 (sufficient for prototype; RS256 for production)
```

### Role Permissions Matrix

| Endpoint | admin | registry_staff | unauthenticated |
|---|---|---|---|
| POST /auth/token | ✅ | ✅ | ✅ (it's the login endpoint) |
| GET /queue | ✅ | ✅ | ❌ 401 |
| GET /cases/{id} | ✅ | ✅ | ❌ 401 |
| GET /cases/{id}/timeline | ✅ | ✅ | ❌ 401 |
| GET /stats/aggregate | ✅ | ✅ | ❌ 401 |
| GET /demo/comparison | ✅ | ✅ | ❌ 401 |
| DELETE /cases (bulk admin) | ✅ | ❌ 403 | ❌ 401 |
| POST /admin/reseed | ✅ | ❌ 403 | ❌ 401 |

### Implementation (FastAPI Depends pattern)

```python
# auth/dependencies.py
def get_current_user(token: str = Depends(oauth2_scheme), db = Depends(get_db)) -> User:
    payload = decode_token(token)  # raises 401 on invalid/expired
    return db.query(User).filter(User.username == payload["sub"]).first()

def require_role(*roles: str):
    def checker(user: User = Depends(get_current_user)):
        if user.role not in roles:
            raise HTTPException(status_code=403, detail="Insufficient role")
        return user
    return checker

# Usage on admin-only route:
@router.post("/admin/reseed", dependencies=[Depends(require_role("admin"))])
```

## 4. Compliance Flags

### CRITICAL — Must be addressed before any demo

| Flag | Requirement |
|---|---|
| **FC-01** | Every page and API response that returns case-level data must include `data_label: "SYNTHETIC"`. No exceptions. |
| **FC-02** | The disclaimer banner ("This system provides administrative review priority only...") must be visible on every authenticated page and cannot be dismissed. |
| **FC-03** | No real litigant names, real CNR numbers, or real case details may appear anywhere in the system — including comments, logs, or seed data. |
| **FC-04** | No output of the system (score, bottleneck label, explanation text) may be framed as evaluating a judge, predicting a judicial outcome, or measuring judicial performance. |
| **FC-05** | JWT_SECRET must be loaded from an environment variable or `.env` file. It must never appear in source code or be committed to the repository. |
| **FC-06** | eCourts data must not be accessed by the system in any automated form. The seed generator must not make HTTP calls to eCourts or NJDG. |

### MEDIUM — Should be addressed before demo

| Flag | Requirement |
|---|---|
| **FM-01** | Add `.env` to `.gitignore`. Provide `.env.example` with placeholder values. |
| **FM-02** | Audit log: all `/queue` and `/cases/{id}` accesses should be logged with timestamp, user, endpoint. Write-only in prototype; file or DB table acceptable. |
| **FM-03** | Error responses must not leak internal stack traces. Use a global FastAPI exception handler. |
| **FM-04** | Password validation: minimum 8 characters for any user created during demo setup. |

### LOW — Post-prototype / production path

| Flag | Requirement |
|---|---|
| **FL-01** | Upgrade JWT to RS256 (asymmetric) for production deployment. |
| **FL-02** | Add token refresh endpoint with sliding window. |
| **FL-03** | Replace SQLite with PostgreSQL and enable encrypted connections. |
| **FL-04** | Add rate limiting (e.g., slowapi) on `/auth/token` to prevent brute force. |
| **FL-05** | Replace localStorage JWT storage with HttpOnly cookie + CSRF token for production. |
| **FL-06** | Conduct formal PII audit before any deployment with real court data. |

## 6. Urgent Flags

> [!CAUTION]
> **URGENT FLAG 1 — Synthetic Data Labelling (P0)**
> The single highest-risk event for this project is a SIH judge or evaluator believing the synthetic case data represents real pending cases. This would immediately disqualify the submission and could cause reputational damage. The `data_label: "SYNTHETIC"` field must appear in every API response containing case-level data, and the disclaimer banner must be impossible to miss in the UI. This is non-negotiable.

> [!CAUTION]
> **URGENT FLAG 2 — No Judge Performance Language (P0)**
> Any triage output language that can be read as "Judge X is slow" or "Court Y is inefficient" will be flagged by judicial stakeholders. Review every bottleneck label, explanation template, and UI label before demo. The word "judge" should not appear in any explanation text. The bottleneck `JUDGE_CHANGE` should be displayed in the UI as "Judicial Transition" or "Bench Change" — never "Judge Delay."

> [!WARNING]
> **URGENT FLAG 3 — JWT Secret in Environment Only (P0)**
> The first thing evaluators checking the source code will look for is a hardcoded secret. Use `python-dotenv` + `.env` loading at startup. Fail loudly on startup if `JWT_SECRET` is not set. Include this in the README.

> [!IMPORTANT]
> **Flag 4 — eCourts Scraping Prohibition (P0)**
> Confirm the seed generator makes zero external HTTP calls. This is a legal compliance requirement, not just an ethical preference. If the generator needs calibration data, it must use locally stored CSV files from data.gov.in or manual figures — never live web requests.
