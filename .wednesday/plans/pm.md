## 5. Phase 3 — Triage Engine (Hours 3–5)

**Goal**: Pure Python triage engine produces correct scores for all 1,000 cases with CASE-ALPHA ranked clearly above CASE-BETA.

### Tasks

| # | Task | Acceptance Criteria |
|---|---|---|
| 3.1 | `triage/stall_detector.py`: compute all stall metrics (days_since_substantive, stage_deviation_ratio, adjournment_streak, cohort_age_percentile) | Unit test: ALPHA.days_since_substantive > 250, BETA.days_since_substantive < 30 |

| 3.3 | `triage/scorer.py`: weighted score 0–100, reads weights from `triage/config.py` | ALPHA triage_score > 80, BETA triage_score < 40 |
| 3.4 | `triage/evidence.py`: assembles full evidence bundle JSON | Evidence bundle for ALPHA contains all required fields per architect.md spec |
| 3.5 | `triage/templates.py`: renders explanation text from template | Explanation text for ALPHA contains no invented reasons; all values traceable to evidence bundle |
| 3.6 | `triage/engine.py`: orchestrates all layers, updates all triage fields on `cases` table | `python -m triage.engine` runs without error; all 1,000 cases have triage_score ≠ NULL |

## 11. Assumptions

1. Python 3.11+, Node 18+, `uv`, and `npm` are pre-installed on the development machine.
2. The synthetic dataset (seed_data / nyaya.db) is committed to the repo so the demo can be reset deterministically.
3. The two demo contrast cases (CASE-ALPHA and CASE-BETA) are hand-crafted to guarantee score separation > 40 points.
4. Triage weights are treated as configurable heuristics; the chosen values produce the correct demo narrative.
5. Real NJDG aggregate figures are manually transcribed from the public NJDG dashboard and stored in the DB — not scraped.
6. The SIH demo runs on localhost; no cloud deployment is required for the hackathon presentation.
7. The system will not handle real litigant data at any point during prototype development or demo.
